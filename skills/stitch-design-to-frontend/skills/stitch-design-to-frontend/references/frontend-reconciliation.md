# Frontend reconciliation after Google AI Studio

## Goal
Close the gap between the approved Stitch design and the frontend generated by Google AI Studio without reopening design ideation.

## Inputs
Use the strongest available source pair:

- approved Stitch screenshot/design + AI Studio preview screenshot;
- approved DESIGN.md + generated frontend code;
- approved screen/project accessible via MCP + generated frontend files;
- user-described mismatch when no other evidence exists.

If the approved source of truth is missing, request only the minimum artifact needed to compare fidelity.

## Comparison order
Prioritize structural errors before cosmetic ones:

1. routes/screens and missing content;
2. layout geometry and hierarchy;
3. responsive behavior;
4. typography and text metrics;
5. component dimensions and spacing;
6. color roles, borders, radius, elevation;
7. icon/image treatment;
8. interaction and UI states;
9. motion/micro-interaction details.

## When generating an AI Studio correction prompt
- state the exact mismatch;
- identify the affected component/section/route;
- state the expected behavior/appearance from the approved design;
- preserve everything already correct;
- request targeted code changes, not a fresh redesign;
- ask AI Studio to verify the live preview after the change.

## When directly editing code
If the host has the generated files and the user asks for direct fixes:

1. Inspect package configuration and source structure.
2. Identify shared design tokens, global styles, component-level styles, and responsive logic.
3. Trace each mismatch to the smallest responsible rule/component.
4. Prefer systemic token fixes when several mismatches have the same root cause.
5. Prefer local fixes when the issue is isolated.
6. Preserve working dependencies, state logic, and unrelated routes.
7. Run available checks such as build, typecheck, lint, tests, or preview where feasible.
8. Report only checks actually executed.

## Completion criteria
The implementation is ready when the user confirms acceptable fidelity or the available evidence shows that the requested discrepancies have been corrected and the frontend code has been exported/synced for continued development.
