# Stitch visual review and iteration

## Reconstruct intent first
Review the result against the design contract, not personal taste. Re-establish:

- product objective;
- user/task;
- primary action;
- approved decisions;
- expected flow;
- brand/system constraints.

## Diagnostic layers

### Structure
Check screen inventory, section order, navigation model, task sequence, missing content, and unnecessary content.

### Hierarchy
Check first focal point, relative emphasis of actions, headings, metrics, tables, forms, and supporting content.

### UX
Check affordances, control labels, task flow, primary vs. secondary actions, error prevention, discoverability, and required states.

### Visual system
Check typography, spacing, density, contrast, color roles, surface treatment, borders, radii, shadows, iconography, imagery, and motion language.

### Content
Check plausibility, length, tone, labels, placeholder realism, and whether content is distorting the intended layout.

### Responsive
Check reflow, navigation transformation, reading width, dense data handling, action persistence, stacking order, touch targets, and overflow.

### Consistency
Check repeated spacing, type, color, component, icon, state, and interaction rules across screens.

## Correction severity
- **Local:** one component or section; preserve everything else.
- **Systemic:** repeated token/component issue; fix the shared rule and verify affected screens.
- **Replan:** core information architecture fails the user task. Explain why before replacing approved structure.

## Response discipline
Prioritize the few highest-impact problems. State what works and must remain. Correct only what is necessary. Never infer final approval from positive partial feedback.
